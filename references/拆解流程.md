# Mode A 拆解流程

## 1. 先建立素材证据卡

记录：

- 平台、作者、链接、发布时间和读取时间；
- 可见点赞、收藏、评论、分享、播放等数据；
- 原文/字幕/页面是否完整取得；
- 封面、标题、正文、评论区分别来自哪里；
- 哪些内容无法访问或只能推测。

平台页面无法访问、没有登录态或抓取失败时，要明确说明没有读取到什么。用户已粘贴完整文字时，不必为了形式重复联网。

若同时提供视频和文案，以视频实际表达为主；若文案与视频不一致，单独标出差异。封面不清楚但不影响核心拆解时可以继续，不要例行停下来追问。

## 2. 先判断标题与封面是否建立点击理由

小红书重点看封面与标题如何让用户点入；抖音、视频号重点看首帧、字幕和前 3 秒如何让用户停留。

建立关键词证据表：

| 词或表达 | 位置 | 面向谁 | 触发什么需求/情绪 | 可见证据 | 证据等级 | 风险 |
|---|---|---|---|---|---|---|

证据等级：

- 候选：只在单个高表现样本中出现；
- 高优先：多个同类高表现样本反复出现，或当前项目 / 当前账号的多条可比样本持续优于同项目同类型基线、但仍存在混杂变量；
- 已验证：当前项目 / 当前账号经过多次可比测试后，稳定优于同项目同类型基线，且该机制是可归因的主要变量。必须标明项目作用域，只在该项目内成立；外部爆款案例不能直接成为任何项目的“已验证”。

标题关键词不等于感觉词。标题词主要完成圈人、场景、问题、结果、反差或时效任务。

## 3. 按观众行为链拆解

不要先套“钩子—痛点—干货—金句”。先回答：

1. 谁会点开或停下来？为什么？
2. 开头建立了什么未完成期待？
3. 中间每一段新增了什么场景、事实、判断、情绪、方法或转折？
4. 观众为什么继续看，而不是已经得到答案就离开？
5. 内容如何建立可信度？来自经历、过程、证据、细节、身份还是表达方式？
6. 点赞、评论、收藏、转发和关注分别可能由什么触发？没有就写没有。
7. 结尾兑现了什么，还把观众带向哪里？
8. 标题承诺与正文是否匹配，有没有过度承诺？

“情绪流动”不是每段塞情绪词，而是观察观众感受是否发生识别、紧张、好奇、被理解、意外、释然或行动冲动等变化。“信息推进”也不等于必须输出方法，具体判断或新场景同样可以构成增量。

## 4. 判断内容任务与素材形态

外部内容也按两层标注：

- 主任务：流量型 / 信任型（人格信任或专业信任）/ 转化型；
- 素材形态：观点型 / 价值观型 / 案例型 / 工作现场型 / 方法型 / 经历型 / 复盘型。

如果一条内容兼有多个目标，选一个“主要任务”，其余写为次要作用。不要因为出现产品或职业就自动判成转化型。

## 5. 分析表达机制

逐段或逐句标注其“观看任务”，而不是只标情绪句/干货句：

- 圈定对象；
- 建立问题；
- 制造期待；
- 补充事实；
- 推进判断；
- 回应反对意见；
- 建立证据；
- 制造互动；
- 完成兑现；
- 给出下一步。

另外分开提取：

- 标题关键词：负责点击、搜索或圈人；
- 口语表达动作：如提醒、拉近、转折、翻译、下判断、回扣；
- 感觉词：增强私密、递进、证据、反常识或情绪感受。

感觉词删除后若一句话没有事实、场景或判断，就不是“有效包装”，而是空表达。完整规则见 [小姜表达机制使用规则](小姜表达机制使用规则.md)。

为供 Mode B 按问题检索，额外将上述观察归纳为机制字段：开头机制、前 3 秒任务、观看理由、核心冲突、信息推进方式、延迟答案方式、证明方式、情绪变化、结尾功能。这里记录的是“该内容怎样帮助观众点进、停留、看完”，不是可直接套用的成品结构。

## 6. 提炼可迁移与不可迁移内容

可迁移的通常是：

- 用户问题和观看动机；
- 信息释放顺序；
- 开头承担的功能；
- 证据出现的位置；
- 回应反对意见的方式；
- 结尾如何承接前文。

每个可迁移机制必须记录：机制 ID（`案例文件名#机制短名`）、机制名称、机制功能、解决的传播问题、为什么在原案例有效、成立条件、适合素材、适合人设、不适合情况、不借什么和证据等级。每一项以“机制功能 + 适用条件”记录，并同时写清不借什么；不要记录成按段落复刻的模板。

不可直接迁移的通常是：

- 作者独有经历、客户案例和数据；
- 标志性原句、独特比喻和完整标题；
- 依赖作者身份或粉丝关系才成立的表达；
- 与当前项目人设、服务边界或证据能力冲突的做法。

## 7. 默认输出与完整输出

默认简明拆解包括：素材证据、目标观众、标题/封面、开头、信息推进、可信度、互动/转化、可迁移点、不可照搬点、风险和结论。

只有用户明确要求“逐句/完整/培训用”时，才使用 [拆解卡模板](拆解卡模板.md) 的完整字段和时间轴。

## 8. 入库

先展示拟入库内容，用户确认后：

1. 写入对应赛道案例卡；
2. 更新 `README_案例库索引.md`；
3. 只把真正新增且有价值的机制追加到相关聚合库，避免重复；
4. 标明内容任务、素材形态、表达强度、人设适配、证据等级、传播机制字段、可迁移与不可迁移项；
5. 保留来源链接与读取时间。

单条外部样本只提供候选机制。没有当前项目 / 当前账号的可比测试数据时，不把词或结构写成“已验证爆款公式”。
