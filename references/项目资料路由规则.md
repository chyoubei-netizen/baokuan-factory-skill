# 项目资料路由规则

本文件只定义 Mode B 如何识别项目并找到资料。真实的项目映射、飞书 URL / token、客户资料和本地私有路径只保存在本地私有知识库的“项目资料索引”，不得写入本 Skill 仓库。

## 1. 先识别项目

按以下线索确认当前项目：当前对话、当前工作目录、用户指定项目、项目简报、本地私有项目资料索引。确认后得到：

```text
project_id
project_name
project_scope: self / client
project_aliases
```

`project_scope` 必须来自项目简报或本地私有项目资料索引的明确字段，不得按项目名称、人物名字或关键词猜测。若有多个可能项目且会影响人设、表达偏好或历史稿读取，只问：`这条是给哪个项目/账号写的？`

## 2. 按项目路由最小资料

确认项目后，读取本地私有项目资料索引中该 `project_id` 的最小必要条目，再决定是否读取：

- 项目简报或客户人设文件；
- 项目表达规则；
- 飞书正文来源（文档、文件夹或知识空间，可多个）；
- 飞书内容状态来源（如 Base/多维表格）；
- 正文与状态记录的匹配键；
- 用户认可、拍摄、发布、复盘的字段和值域规则；
- 项目案例和发布数据位置。

索引没有配置的资料不猜测、不跨项目搜索；当前任务不需要的资料不读取。

## 3. 表达规则作用域

- 所有项目：加载全局操盘偏好。
- `project_scope = self`：加载本人表达偏好与全局操盘偏好。
- `project_scope = client`：加载该项目简报/客户人设文件与全局操盘偏好；本人表达偏好不得介入。

项目表达规则优先于全局操盘偏好；真实性、人设、业务和合规边界始终优先于表达偏好。

## 4. 飞书正文与状态联合路由

仅使用当前 `project_id` 在私有索引中明确登记的飞书来源。正文库负责提供稿件原文；Base 等状态源负责判断稿件是否被用户认可、是否已拍、是否已发布和是否已复盘。不要因为文档放在飞书里，就自行猜测它的状态。

若项目配置了状态源，默认顺序是：

1. 读取真实字段结构，确认内容状态、拍摄状态、发布状态、复盘状态、项目字段和正文链接字段；
2. 按项目索引配置的“认可状态值”筛出最近约 5—10 条认可稿；
3. 优先按文档 URL/token 精确匹配正文；没有 token 时才用项目内唯一的完整标题匹配；标题重复或匹配不唯一时停止猜测；
4. 回读正文，提取本次需要的开头、观点路径、证明、案例、结尾、业务露出和结构指纹；
5. 表中没有登记但用户在当前对话明确认可的稿件，可以加入本轮认可集合，并标记证据来源为“用户本轮确认”。

一个项目可有多个正文来源和状态来源，先按 `project_id` 分别筛选，再合并去重。不得默认搜索整个飞书，或因选题相似读取本人账号、其他客户或其他行业的内容。

### 状态的四种用途

- **表达学习**：只使用用户明确认可的稿件。认可状态值由项目索引配置，不要求已经发布。
- **跨稿去重**：使用近期认可稿；必要时可加入近期已写但未认可稿作为“候选冲突”，但必须单独标记，不能冒充正面样本。
- **效果学习**：只使用已发布且有真实数据的稿件；“已复盘”优先级最高。
- **负面学习**：只有用户明确否定，或项目状态明确配置为负面/作废时才使用；“以前的稿件不太适合”可以降低其风格参考权重，但不自动把每一篇都登记为负面样本。

拍摄状态和发布状态不得覆盖内容认可状态。例如“内容状态=审核通过可拍摄、拍摄状态=未拍、发布状态=未发布”仍代表文案已经审核通过。

通过当前可用且已授权的飞书能力真实读取；只取本次所需字段，不把全文复制进个人表达模型。

若飞书访问不可用、来源缺失、项目无法确认或无法筛出合格稿，记录：

```text
近期认可文案：未成功读取
原因：飞书访问不可用 / 项目未配置正文来源 / 项目未配置状态来源 / 项目未确认 / 状态与正文无法可靠匹配 / 无法筛出认可稿
跨稿去重：本次降级执行
```

仍可在已有事实基础上创作，但不得声称已完成历史稿去重。
