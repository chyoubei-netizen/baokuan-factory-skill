# 文案引擎：从真实素材到可拍口播

本文件用于 Mode B 的“写稿/改写”阶段。它解决的不是词藻，而是：有了一个想法后，怎样先搭出真实、可停留、可相信的内容骨架。

不要把以下卡片逐份抛给用户。优先用已知资料完成；只有真实事实缺失且会影响成稿时，按主技能的问题闸门问 1—3 个问题。

## 1. 先判断用户所处阶段

内容主任务和用户认知阶段要一起判断。

| 用户阶段 | 用户心态 | 更适合的内容任务 | 常见内容重点 |
|---|---|---|---|
| 尚未意识到问题 | “这有什么关系？” | 流量型 | 场景、反差、让他看见问题 |
| 知道有问题但不急 | “好像是这样，但没必要改” | 流量型或信任型 | 损失、误区、重新定义问题 |
| 想解决但不知道怎么做 | “那我该怎么办？” | 专业信任 | 判断标准、过程、方法、可用动作 |
| 正在比较方案或服务者 | “为什么选你？会不会踩坑？” | 转化型 | 证据、边界、适合/不适合、低压力下一步 |

这不是把每个用户塞进唯一标签，而是用来决定：开头该先让他意识到问题，还是直接回答他的选择顾虑。

## 2. 文案事实骨架卡

写正文前，内部填以下内容。事实、对话、案例、数据和结果必须来自用户提供、项目资料或可核实素材；不够时标 `【待补充】`。

```text
目标用户：
他现在处于什么具体场景：
他表面上在做什么：
他真正想得到/避免什么：
他付出的投入、等待、损失或落差：
他通常相信的旧认知：
本条要给出的新判断：
我能用什么证明：现场 / 原话 / 过程 / 案例 / 数据 / 专业判断：
观众最终应获得什么：相关感 / 理解感 / 判断感 / 方法感 / 自检感 / 行动方向：
```

### 使用规则

- 纯观点或人格内容也要有具体事件、观察或处境，不等于一定要有业务案例。
- 0 级业务露出时，“证明”可以是个人经历、具体观察或价值观行动；不要为了证明专业强拉服务。
- 1 级优先使用工作现场、客户问题、交付过程和判断细节。
- 2 级必须有能回应比较顾虑的真实证明；没有时降为 1 级专业信任。
- “效率低、没有效果、很专业、很负责”不算场景或证明。要改写成用户做了什么、等了多久、卡在哪里、发生了什么变化。

### 事实骨架之后，才调用案例机制

先由真实素材与本条观点决定内容要说什么；再判断它最需要解决的传播问题：开头停留 / 中段推进 / 证明 / 情绪 / 结尾 / 转化承接。仅在问题明确时，从案例索引匹配 1—2 个案例，最多确定 1 个主机制和 1 个辅助机制。

案例机制只提供传播功能，例如让开头留下什么未完成期待、在哪一处放证明、怎样延迟答案或怎样回应反对意见；它不能替换事实骨架、决定核心观点，也不能覆盖项目事实、人设与表达规则。本人项目的落笔顺序是：真实素材与本条观点 > 本人表达偏好 > 选中的传播机制 > 历史案例句式。

## 3. 开头锻造卡

开头不是把标题换一种说法。它要先打断目标用户的旧预期，再留下后文要兑现的问题。

先完成：

```text
用户旧认知：
反差/落差：投入与结果、表面与原因、愿望与代价，或身份与现实：
本条新判断：
可核实的场景或证明：
标题承诺：
```

然后根据人设与素材，优先从下列入口中选择 1 个主版本；方向明显有分歧时可给 3 个不同机制的备选，而不是同义改写。

### A. 场景冲突

适合：有动作、对话、现场或反差画面。

结构：`具体人/动作 + 意外落差 + 未完成问题`

例：`有些老板聊天时能讲半小时，镜头一开，第一句就只剩“大家好”。`

### B. 旧认知反转

适合：有明确、可解释的新判断。

结构：`目标用户以为 X，真正卡住的却是 Y。`

例：`老板拍口播最怕的，往往不是不会说，而是太想把每一句都说对。`

### C. 投入与结果落差

适合：用户确实有时间、金钱、精力或机会成本的真实损失。

结构：`具体投入 + 没得到的结果 + 反问/判断`

例：`一条口播稿改了三天，开拍还是说不出来，问题可能根本不在稿子。`

### D. 真实经历进入

适合：人格信任或工作观察。

结构：`具体事件 + 当时反应 + 后来发现的判断`

例：`昨天拍到一半，我反而让客户先别背稿了。`

### 开头验收

- 是否明确让目标用户知道“这和我有关”？
- 是否包含真实的场景、判断或落差，而非泛泛提醒？
- 后文是否有事实、原因或过程兑现？
- 强度是否符合人设和证据？
- 删除“真相、其实、你知道吗”等语气词后，开头还成立吗？

没有真实落差时，不强造冲突。平静人设可以用一个具体观察开头，力度来自判断清楚，不来自高声量。

## 4. 证明选择器

先选一种最适合本条内容的证明，不把所有证明堆进一条视频。

| 证明方式 | 适用内容 | 最低要求 | 常见误用 |
|---|---|---|---|
| 工作现场 | 专业信任、服务过程 | 具体动作、判断或调整 | 把“我们很专业”当过程 |
| 用户原话 | 痛点、异议、共鸣 | 可公开且真实的表达 | 编造客户台词 |
| 个人经历 | 人格信任、价值观 | 具体事件和真实感受 | 苦难叙事替代观点 |
| 案例 | 转化、专业信任 | 人物情境、动作、变化；必要时匿名 | 虚构结果或夸大效果 |
| 数据 | 需要量化比较 | 来源、口径、时间范围 | 用孤立数字暗示必然结果 |
| 专业判断 | 观点、方法、复盘 | 判断过程或判断依据 | 只下结论、不解释 |

若证明无法公开，写成可拍的过程细节，或删掉该结论；不要用模糊的“我做过很多”“客户都说好”替代。

## 5. 按任务搭正文

下面是可选骨架，不是固定模板。先由当前素材决定最自然的推进方式，再检查近期认可稿是否已经反复使用相同的开头、转折、证明和结尾。深度来自新的因果解释、判断依据或观察对象，不来自“真正、本质、其实”等词，也不要求每条内容都下探到一个宏大模型。

### 流量型

`场景/反差 → 让人意识到问题 → 给出新判断 → 解释或延迟答案 → 兑现一个理解/判断 → 回扣`

重点是扩大相关人群，不为了播放把话题做成与账号完全无关的泛情绪。

### 人格信任

`事件 → 当时的感受或矛盾 → 为什么这样想 → 做出的选择/行动 → 留下真实判断`

可以是 0 级业务露出。不要为了商业连接破坏一条本来成立的人物内容。

### 专业信任

`真实工作场景 → 常见误判 → 专业判断 → 怎么处理/为什么 → 过程细节或结果边界`

重点是让能力被看见，而不是讲一堂基础课。

### 转化型

`购买顾虑 → 真实场景 → 原因/判断标准 → 适合的解决方式 → 证据与边界 → 一个低压力下一步`

转化型先回答“为什么需要、为什么可信、是否适合”，最后才允许行动引导。

### 结构防同质化检查

落笔前任选最适合当前材料的一条真实推进路径，不追求覆盖全部：

- 从一个具体动作连续展开，不做抽象升华；
- 从一个判断直接解释依据，用事实收尾；
- 从经历按时间推进，保留当时的误判和变化；
- 从一个反对意见进入，只回答这一件事；
- 从一个业务现象推演，但允许结尾停在未完全解决的问题；
- 从过程或对比进入，让证据先于观点出现。

审稿时反查：删除最后的总结金句后，正文是否仍有价值？如果没有，说明所谓深度主要靠包装；如果整篇换一个选题仍能套用，说明结构还没有真正属于当前素材。

再检查：这是否只是把某一案例的结构换成行业词？是否同时拼接了过多机制？传播机制是否抢走了本条真实的思考过程？若任一答案为“是”，保留最必要的机制，回到事实骨架重写推进。

## 6. 模板测试标签

文案不是一次性作品。发布包或复盘时，为本条记录：

```text
内容模板：场景冲突 / 工作现场 / 客户问答 / 案例复盘 / 观点判断 / 经历故事……
本次测试假设：
本次只测试的变量：开头 / 标题 / 证明方式 / 拍摄形式 / 结尾承接……
原定目标指标：
目标用户是否出现：用评论、主页访问、私信或咨询判断
对照基线：同账号、同平台、同内容任务的近 5—10 条（没有则标缺失）
下一轮保留/替换的变量：
```

每轮尽量只改 1—2 个变量。没有数据时保留“待验证”，不要把一次表现归因给某一个词或模板。
